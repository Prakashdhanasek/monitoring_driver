Driver Verification to Trip Completion

Complete Operational Flow & Technical System Architecture Document

Driver Monitoring System (DMS) Technical Specification Demo & Presentation Guide

1. Overall Flow Overview

The system execution workflow moves through the following standardized lifecycle:

    Application starts and initializes system modules. Face Verification Screen opens and front camera activates. Driver verification attempt begins using facial recognition. System routes to the appropriate flow based on:
      Case 1: Verified Driver (Registered face match) Case 2: Unknown Driver (Unregistered face / Verification failure) Case 3: Speed-Triggered Trip — No Face Detected (Vehicle motion > 20 km/h)
    Trip session starts officially. Monitoring Screen runs continuously with AI detection engines. Incidents, alerts, and live GPS/video telemetry are transmitted to the backend. Trip-end conditions are evaluated continuously. Trip completes, data synchronizes, and app returns to the Face Verification Screen.

2. Detailed Case Execution Workflows

Case 1: Registered Driver — Face Matches
Normal Successful Flow

Step-by-Step Order:

    App Launches: System opens the Face Verification screen and turns ON the front camera to monitor the driver seat area. Driver Seated: Driver sits in front of the camera; live face frame is captured. Face Comparison: Live facial features are matched against enrolled driver face templates uploaded via the Admin Panel. Consistent Match Check: Verification requires 2 to 3 seconds of continuous matching (or ~3 consecutive matching frames) within configured confidence thresholds to prevent false positives. Verification Succeeds:
      Green Verified screen is displayed with message: “Welcome, [Driver Name]!” Voice greeting plays in driver's preferred language (Supports: English, Hindi, Malayalam, Tamil, Kannada).
    Trip Starts: System transitions to the Monitoring screen. A Trip Start telemetry payload is dispatched to the backend with: Device ID, Driver ID, Driver Name, GPS Coordinates, and Timestamp.

During the Trip:

    Continuous Detections: Drowsiness, Sleep, Distraction, Phone usage, Smoking, Eating/drinking, Seatbelt usage, Overspeed, Geofence breach. Telemetry Stream: GPS telemetry pushed every 3 seconds to backend. Incidents reported following cooldown rules. Driver Continuity Check: System continuously checks if the verified driver remains in the seat. If a different face is continuously detected for 5 seconds, a DRIVER CHANGED alert is triggered and reported.

Trip Ending Logic:

If the driver's face disappears from frame:

    A 5-second grace period initiates. Followed by a 30-second countdown. If face remains absent for a total of 35 seconds, the trip completes, data synchronizes, and system returns to Face Verification.
Case 2: Unregistered Person — Face Does Not Match
Unverified / Stationed Driver Flow

Step-by-Step Order:

    App Starts & Face Captured: Camera detects a person sitting in the driver's seat. Face Comparison: System compares face against enrolled drivers; threshold is not met. Retry / Continuous Checking Phase (10 Seconds): The system continues attempting matching for approximately 10 seconds to prevent false failures from poor lighting or head angles. Verification Failure: If no match is found after 10 seconds:
      Voice alert plays: “Driver verification failed.” Driver identity marked as Unknown Driver.
    Trip Starts as Unknown Driver: System moves to Monitoring screen. Trip Start payload sent with: Driver ID = null / unknown, Driver Name = Unknown Driver. Monitoring Active: All major safety features run (Drowsiness, Distraction, Phone, Smoking, Seatbelt, Overspeed, Geofence). Driver Change Detection is disabled (no baseline identity). Trip Ends: Trip finishes based on standard driver-leaving rules (35s absence countdown), shows Trip Completed screen, and resets.
Case 3: Speed-Triggered Trip — No Face Detected
Safety Priority Flow (Speed > 20 km/h)

Step-by-Step Order:

    App Starts & Camera Active: App is on Verification Screen. Driver seat is empty or face is unreadable (camera blocked / bad angle). Vehicle Motion Detected: Vehicle speed exceeds 20 km/h. Verification Skipped: Safety system skips verification phase immediately to prioritize driver safety monitoring. Trip Starts Immediately: Opens Monitoring Screen with no identified driver. An Unverified Driver incident is logged to the backend. Active Monitoring & Late Driver Identification:
      All safety monitoring modules run continuously. Mid-Trip Identification: If a face appears later and matches a registered driver, the active trip is dynamically updated with the Driver Name & ID, restoring Driver Continuity checks. If non-matching, it remains an Unknown Driver trip.
    Speed-Triggered Trip End Logic: When vehicle speed drops below 6 km/h and remains below 6 km/h continuously for 30 seconds, the trip completes, data syncs, and system resets to Face Verification.

3. Monitoring Order & Core Detection Modules

Post-Verification Monitoring Sequence: Once verification is complete or bypassed, the trip state becomes active. The status bar displays Trip Number, Driver Name / Unknown, Connection Status, Vehicle Speed, and Camera Health.

The following continuous AI monitoring engines operate during active trips:

    Facial Landmark & Head-Pose Engine: Tracks yaw/pitch orientation for distraction. Drowsiness Engine: Calculates Eye Aspect Ratio (EAR) and PERCLOS eye closure rates. Object Detection Model: Identifies cell phones, smoking/cigarettes, eating/drinking. Safety & Compliance Rules: Seatbelt status, Overspeeding thresholds, Geofence boundaries. Alert & Evidence Dispatcher: Triggers visual banners, TTS audio, backend incident alerts, and snapshot/video clip evidence with configured cooldown rules.

4. Trip Termination Rules Summary

Trip Condition Primary Termination Trigger Grace Period / Timeout System Action
Standard Trip (Verified / Unknown) Driver face disappears from camera frame 5s grace + 30s countdown (35s total) Complete trip, sync data, return to Verification Screen.
Speed-Triggered Trip (No Face) Vehicle comes to a halt / low speed Speed < 6 km/h for 30 continuous seconds Complete trip, sync data, return to Verification Screen.

6. Presentation & Demonstration Script

🎙️ Official Evaluator / Client Presentation Script

“When the application starts, it first opens the Face Verification screen and activates the front camera. The system waits for a driver to appear. If a registered driver sits in front of the camera and the live face continuously matches the enrolled face images for approximately two to three seconds, the driver is verified, a welcome message is displayed, and the trip starts with that driver's identity.

If a face is detected but does not match any registered driver, the system continues trying for approximately ten seconds while the vehicle is stationary. If no valid match is found, verification fails and the trip starts as an Unknown Driver trip.

If no face is detected at all and the vehicle starts moving above twenty kilometers per hour, the system completely skips verification and starts the trip immediately so that safety monitoring can begin without delay. An Unverified Driver incident is also generated. If a face appears later and matches a registered driver, the current trip is updated with that driver's identity.

After verification or fallback, the monitoring phase begins. During the trip, the system continuously monitors drowsiness, distraction, phone usage, smoking, eating, drinking, seatbelt usage, overspeed, and geofence violations.

If the trip starts with a verified driver, the system also continuously checks whether the same driver remains in the driver's seat.

At the end of the trip, if the driver's face remains absent for the configured duration, or, in a speed-triggered no-face trip, if the vehicle remains below six kilometers per hour for thirty continuous seconds, the trip is completed. The trip data is synchronized, the Trip Completed screen is displayed, and the system returns to the Face Verification screen.”
